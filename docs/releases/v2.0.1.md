Maintenance & documentation release upgrading the database layer to **PostgreSQL 18** and expanding the repository documentation with real rendered chart previews, ER diagrams, and operational runbooks.

---

## What Changed

### PostgreSQL 18 (`postgres:18-alpine`)
- Upgraded `docker-compose.yml` from `postgres:17-alpine` to `postgres:18-alpine`.
- Adopted the official PostgreSQL 18+ volume mount path (`postgres_data:/var/lib/postgresql`), which stores cluster data under `/var/lib/postgresql/18/docker` to streamline future `pg_upgrade` operations.
- Added a step-by-step **PostgreSQL 17 → 18 dump & restore runbook** in [`docs/DEPLOYMENT.md`](../DEPLOYMENT.md#5-upgrading-postgresql-17--postgresql-18).

## Upgrading from `v2.0.0` (PostgreSQL 17 → 18)

Because PostgreSQL 18 cannot mount a PG 17 data directory in place, run a clean `pg_dump` before recreating the database volume:

```bash
docker exec expenses-postgres pg_dump -U "${EXPENSES_DB_USER:-expenses_user}" "${EXPENSES_DB_NAME:-expenses_db}" > backup_pg17_$(date +%Y%m%d).sql
docker compose down
docker volume rm hermes-finance-stack_postgres_data
git pull origin main
docker compose up -d --build postgres
docker exec -i expenses-postgres psql -U "${EXPENSES_DB_USER:-expenses_user}" -d "${EXPENSES_DB_NAME:-expenses_db}" < backup_pg17_$(date +%Y%m%d).sql
docker compose up -d --build
./scripts/smoke-test.sh
```
